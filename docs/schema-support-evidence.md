# Schema capability and pairing index

The supported AKA engineering profile is Linux, Python 3.13, the four matching
Framework/Legacy/Light/Schema distributions from a reviewed source checkout,
and the KS checkout pinned in [release.json](../src/aka/workflow/schema/release.json).
Python 3.11 remains unverified. Follow the [source installation procedure](schema-source-release.md)
and run `verify_release()` in the installed interpreter from a different cwd.
The package version alone does not identify these sources.

| AKA path | Implemented and exercised with CPU synthetic transports | Actual qualification required |
| --- | --- | --- |
| Default / `--no-schema` | Original native loop; no optional import, KS checkout access or download; normalized upstream/off comparison | Existing native workflow requirements |
| `--schema`, empty backend parameters | Fixed row-softmax request, exact seed or `verify_only`, same-R episodes, durable C and three native audits | Native coder/reviewer, complete CUDA Task and independent current-R fidelity |
| `--schema`, explicit `parameters.dynamic` | No-Schema design or an existing Schema, fixed stage, at most one optimize, then an explicit Source/default-start implementation or verify action | Actual writing and fixed-stage records for the executed chain |
| `kernelschema implement`, backend `aka` | Synchronous fixed controller using the supplied RunContext and original parent authority | The same AKA native and Task qualification as the AKA entry |
| Native transport probe | Original Agent/NativeSession, exact role input, no-tools initialization, input/exec/invocation capture and at most two calls | A successful original coder and reviewer capture; timeout or unknown usage does not qualify |

AKA supports only the complete row-softmax Task with `single_file/kernel.py`,
Triton, `framework_baseline=never`, no stack conversion and no hard token limit.
The native V0 is still required. Baseline V0, selected C, incumbent G, HEAD,
current Schema qualification and promotion remain separate facts. An unconfigured
service returns the original zero-fee blocked result.

The engineering evidence uses actual KS APIs, original native Campaign/Store/Git,
RoleSession, bootstrap and CLI entry points. The synthetic model process,
CUDA-success observations and same-allocation comparison fixture are identified
in their test artifacts. They do not sign MODEL/GPU gates. The test sources are:

- [dynamic paths](../tests/test_schema_dynamic.py), [original CLI](../tests/test_schema_dynamic_cli.py),
  [stage recovery](../tests/test_schema_dynamic_recovery.py), and
  [final admission/action review](../tests/test_schema_dynamic_final_review.py).
- [fixed controller and audits](../tests/test_schema_backend.py),
  [source lifecycle](../tests/test_schema_seed_lifecycle.py),
  [native transport](../tests/test_schema_native_probe.py), and
  [business/probe interval limits](../tests/test_schema_native_limits.py), plus
  [off isolation](../tests/test_schema_off.py).

## A7.pair engineering differences

This comparison identifies integration differences. A7.pair remains unsigned
until each backend has its own applicable real records for the same Task,
source and complete acceptance method. No backend's pass substitutes for another.

| Concern | AKA adapter | KS reference path |
| --- | --- | --- |
| Public contracts, Source and selected artifact closure | Consumes the fixed KS implementation | Owns that common implementation |
| Code execution owner | Original native Campaign and episode lifecycle, with KS OwnerAccount for fees | Finite KS reference controller and the same OwnerAccount API |
| Planner scheduling | Explicit finite dynamic selection calls KS writing APIs | Finite standalone driver calls the same APIs |
| Candidate continuation | Stable C enters the next draft on the retained native HEAD; G and native limits persist | Explicit stable C enters the next reference invocation |
| Full Task evaluation | SchemaEvaluator/CommandEvaluator invoke the selected KS channel with unchanged Task reports | Direct selected KS channel |
| Promotion and comparison | Native audits and one-allocation ABBA protocol; concrete Agate comparison remains unselected | No native promotion requirement; Task timing is reported separately |
| Source trees / FA4 F1 | Outside this AKA release's support | Implemented in the KS reference path; real CuTe/SM103 qualification remains separate |

The public [KS standalone guide](../optional/KernelSchema/docs/workflows/standalone.md)
owns the reference backend's detailed scope. A7.fixed, A6.real and A7.pair still
need applicable real native, full-Task, fidelity and delivery evidence. GPU/auth,
remote dev permissions, read-only execution and Agate same-allocation behavior
have not been qualified by these CPU checks. Public Task timing cannot stand
in for native ABBA. Source-only installation excludes private capture directories
and preserves the original AKA LICENSE/NOTICE and each dependency's own notices.
